Working on **SIH 2026 PS 26167 (ISRO / Dept. of Space): "SatQuery AI"** — an agentic vision-language assistant answering natural-language queries over remote-sensing imagery. Was weighing this against **PS SIH26173 "iTantra"** (also ISRO, Indic speech/offline low-bitrate multilingual); as of 2026-08-27 leaning SatQuery and targeting a **nationals-grade** build (not just the college internal round).

**Why this shape of solution:** PS mandates five things — RS adaptation of a visual/VL component, single-image VQA plus caption-or-grounding, bi-temporal change description/VQA, optical–SAR joint extraction, and agentic orchestration with an auditable trace. A generic VLM is explicitly disqualified. Team has only 1-2 ML-capable members on free-tier T4/P100.

**Key decisions made (documented in two design docs produced 2026-08-27):**
- **Do not fine-tune anything above 3B.** Qwen2.5-VL-3B QLoRA as the VQA/caption target; GeoChat-7B used only as a zero-shot baseline for comparison.
- **Two-track adaptation** — this is the central insight. BigEarthNet is 120x120 @ 10m but the private ISRO eval is Cartosat-2S (~0.65-1.6m) + RISAT SAR, a ~15x resolution gap. So: Track A = band-agnostic encoder (CROMA or DOFA) adapted on BigEarthNet for multi-sensor/land-cover/optical-SAR, then laddered 10m → WHU-OPT-SAR 5m → Cartosat scale; Track B = high-res object-level instruction tuning on VRSBench/RSVQA-HR/DIOR-RSVG. Bridged by band-presence masking + random band dropout + GSD-conditioned scale augmentation.
- **Constrained planner over a version-controlled capability matrix**, not free-form LLM tool-calling — because PS evaluates only the observable trace, so determinism and provably-legal plans win.
- **Differentiation deliberately placed where GPU is not the bottleneck:** physics-in-the-loop verifier (NDWI/NDVI/NDBI + SAR sigma0 thresholds independently checking VLM claims), three-component calibrated confidence with abstention + risk-coverage curve, entailment-gated synthesis, georeferenced evidence packs, full audit trace.
- **Stub-first architecture** so the four non-ML members are never blocked on GPU work.

**How to apply:** when they return to this, the highest-leverage open action is pulling real **Cartosat-2S + RISAT scenes from ISRO/NRSC Bhoonidhi** (long lead time — was flagged as a day-one task) plus Umbra/Capella open sub-metre SAR as a RISAT proxy, to build an internal held-out eval set against the secret ISRO test set.

**Final consolidated build plan delivered 2026-08-27** (six English markdown docs, ~23k words, in the session outputs folder: `00-README-and-Requirement-Traceability`, `01-Solution-Architecture-and-System-Design`, `02-Agentic-Workflow-and-Orchestration`, `03-Models-and-Datasets`, `04-Implementation-Plan`, `05-Innovation-and-Extra-Features`). Produced by merging five AI design passes (ChatGPT, Grok, Gemini, two prior Claude docs, Opus 4.8) and adding decisions none of them made. New decisions beyond the list above:

- **Cartosat-2S MX is 4-band VNIR with no SWIR** → MNDWI and NDBI are unavailable on the ISRO eval set. Built-up detection must be SAR-primary (sigma0 + local variance + double-bounce) with optical GLCM texture secondary. This is the single sharpest practical insight in the plan and no competing analysis caught it.
- **RISAT band is ambiguous** (RISAT-1 C-band vs RISAT-2B/2BR1 X-band) → never hardcode absolute sigma0 dB thresholds; use adaptive Otsu/GMM on the histogram. SAR-vs-optical discrimination via coefficient of variation must be done in amplitude (single-look ~0.52, L-look ~0.52/sqrt(L)) not intensity (single-look 1.0).
- **Headless batch eval runner + `run_batch` on every tool from day one**, because the PS's normalised-score evaluation over a large private set makes throughput a scoring risk, not just a UX one. A GUI-only build fails here.
- PNG/JPEG must be gated behind an explicit benchmark-mode flag and rejected in operational mode (PS wording).
- Tile pyramid + query-conditioned coarse-to-fine tile retrieval for large Cartosat scenes; retrieval logged as an auditable planner step.
- Deterministic template path (never generation) for all quantitative answers — counts from detections, areas from the affine transform, increase/decrease from signed subtraction.
- Nine-tool registry but only **four trainings** via deliberate weight sharing + hot-swappable LoRA adapters.
- Cross-modal **complementarity triad** (optical-only / SAR-only / fused) as both a runtime feature and the PS-required proof of complementarity — flagged as the highest marks-per-hour item in the whole plan.

**Verified 2026-08-27** (user supplied the paper PDF `2603.29630v2` after the network fetch stayed blocked): BigEarthNet.txt is confirmed exactly as planned — **464,044** co-registered S1/S2 pairs, **9.6 M** annotations (captions + binary VQA + MCQ + referring-expression + point detection), benchmark split **1,082 pairs / 15,029 annotations** from the test split, manually verified. New load-bearing facts from the paper: (a) it is **European-only and single-timestamp** — images from BigEarthNet v2.0/reBEN over ten European countries, **no change pairs** — so it serves M1/M2/M3/M6 but NOT M4/M5 (change datasets + Bhoonidhi still mandatory); (b) **12-band S2 + S1, SWIR present**; their own RS-InternVL uses only the 10 m+20 m bands (10 bands, drops the 3× 60 m) — mirror for Track A, and our SWIR band-dropout curriculum is now empirically justified; (c) benchmark VQA uses **deliberate hard negatives**; (d) mirror their metrics (BLEU-4/ROUGE/METEOR/CIDEr/BERTScore/SBERT/CLAIR; accuracy; mIoU+Acc@k) for direct comparability. **Killer pitch fact:** their fine-tuned **1B** RS-InternVL (5.8 M trainable params, +S1/S2 branches, LoRA r8) beats GPT-5.2 (2T) and every SOTA RS/CV VLM by **+31.5 % avg** on their benchmark (binary VQA 73.29 vs 61.96; referring mIoU 65.84 vs 31.73; caption BLEU-4 34.04 vs 1.66) — strongest external evidence for the adapt-a-small-VLM thesis. **Compute caveat:** that 1B run took ~2 days on 4× H200 over the full set; on T4/P100 we must subsample the instruction mix hard (tens of thousands, not millions). **InternVL3-1B** is thus a strong backbone alternate to Qwen2.5-VL-3B (register item 6). **Licence + format confirmed 2026-08-27 from the HF dataset card** (`BIFOLD-BigEarthNetv2-0/BigEarthNet.txt`): licence = **CDLA-Permissive-1.0** (permissive open data — free to use/modify/redistribute, no non-commercial or share-alike clause; models trained on it carry no obligation), so there is no licence risk. Format reality: the repo is **467 MB Parquet, 9,553,962 rows = one row per annotation, TEXT ONLY** (columns `ID`/`s1_name`/`patch_id`/query text/…) — the row count matches the paper's 9.55 M annotations exactly. The S1/S2 imagery is **not** included; rows reference patches by id, so the rasters must be pulled separately from BigEarthNet v2.0 / reBEN (tens–hundreds of GB) — that imagery pull, not the 467 MB text, is the real storage cost to budget.
